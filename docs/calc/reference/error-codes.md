# Error codes

Every error carries a stable `code`. Clients should branch on the code, never on the message. When the docs are built, this table is generated by scanning the library's source for every error it raises, so a new code shows up here automatically.

```python exec="on"
import ast
import pathlib

import pylibs_calc
import pylibs_calc.errors as errors

HINTS = {

    "type_mismatch": "Incompatible types, e.g. decimal × float. Cast one side",

    "unsupported_aggregation": "An AG Grid aggFunc with no matching measure",
    "file_not_found": "`register_scan` on a path that doesn't exist",
    "compute_error": "Polars failed on valid input (overflow, bad data)",
    "dataset_not_found": "Unknown dataset, or a version the catalog no longer keeps",
    "scenario_not_found": "Unknown or deleted scenario",

    "limit_exceeded": "Over a `Limits` cap, or a request body over `max_body_bytes`",

    "engine_busy": "No execution slot free within `queue_timeout_s`",

classes = {n: c for n, c in vars(errors).items() if isinstance(c, type) and issubclass(c, errors.CalcError)}
found = {}
root = pathlib.Path(pylibs_calc.__file__).parent
for path in sorted(root.rglob("*.py")):
    for node in ast.walk(ast.parse(path.read_text())):
        if isinstance(node, ast.Call):
            name = getattr(node.func, "id", None) or getattr(node.func, "attr", None)
            if name in classes:
                code = next(
                    (k.value.value for k in node.keywords if k.arg == "code" and isinstance(k.value, ast.Constant)),
                    classes[name].code,
                )
                found.setdefault((classes[name].status, code), set()).add(name)
found.setdefault((errors.Forbidden.status, errors.Forbidden.code), {"Forbidden"})
# pydantic validation problems surface as SpecError(invalid_request).
found.setdefault((422, "invalid_request"), set()).add("SpecError")

print("| Status | Code | Raised as | Meaning |\n| --- | --- | --- | --- |")
for (status, code), names in sorted(found.items()):
    print(f"| {status} | `{code}` | {', '.join(f'`{n}`' for n in sorted(names))} | {HINTS.get(code, '—')} |")
```

## Exception classes

In Python, catch the class and read `.code`, `.path`, `.status` and `.message`:

| Class | Status | Raised when |
| --- | --- | --- |
| `CalcError` | — | Base class of every error below |
| `SpecError` | 422 | The request is not a valid calculation |
| `ComputeError` | 422 | Polars failed on valid input |
| `NotFound`, `DatasetNotFound`, `ScenarioNotFound` | 404 | Something doesn't exist |
| `Forbidden` | 403 | Your `authorize` hook refused |
| `VersionConflict` | 409 | A stale `expected_version` |
| `LimitExceeded` | 413 | Over a `Limits` cap |
| `EngineBusy` | 503 | No execution slot in time |
| `CalcTimeout` | 504 | Past the timeout |

The HTTP body is:

```json
{"detail": {"code": "unknown_column", "message": "unknown column: notionl", "path": "/query/measures/0/of"}}
```

- `path` is a JSON pointer into the request.
- Validation errors also carry `detail.errors`, with up to 20 problems at once.
